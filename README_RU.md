# Mason — самостоятельный оверлей

Это полное активное меню из присланного проекта, отделённое от игровых модулей. Сборка создаёт **MasonOverlay.exe**, а не DLL. Игра, эмулятор, инжектор, драйвер и гипервизор для запуска не нужны. Администраторские права не запрашиваются.

## Что сохранено

- Исходная библиотека ImGui с её собственными тенями и свечением, а не новая похожая оболочка.
- Размер меню 680 × 460, расположение панелей, вкладки, подписи и размеры элементов.
- Entities; World → Visual / Misc; Legitbot → Aimbot / Triggerbot; Skins; Configs.
- Переключатели, ползунки, цветовые редакторы, контекстные окна, анимации, выбор всех 14 названий карт.
- Темы Default, Solid, Solid White, настройка Accent color, Main glow и Logo glow.
- Менеджер конфигов, создание/сохранение/загрузка/удаление локальных конфигов, бинды и виджеты.
- Вотермарк с часами, список биндов, исходный демонстрационный Hit logs, перемещение виджетов при открытом меню.
- Исходные шрифты и набор иконок.

Вкладка Skins была пустой и в активных исходниках; новые элементы в неё не добавлены. Верхняя кнопка Save в Entities сохраняет исходный демонстрационный диалог; настоящий локальный менеджер находится в Configs.

## Что изменено

1. Удалены игровые реализации, чтение/запись памяти, поиск процесса/модулей, хуки и код внедрения, игровой рендеринг, данные коллайдеров и старые результаты сборки. Никакие исходные DLL или другие исполняемые файлы не включены.
2. Все игровые настройки перенесены в `product/ui_state.hpp`: это только локальные bool/int/float/цвета/строки. Они могут менять вид своего переключателя или сохранённое значение, но ничего не делают с игрой и не рисуют ESP/FOV/прочие игровые эффекты.
3. Даже переключатель `Overlay` в World → Misc — только локальное значение. Исключения из записи экрана нет.
4. Kill Sound сохраняет исходный список имён `.wav` и настройку громкости, но код воспроизведения полностью удалён.
5. Прежнее имя заменено на **Mason**, папка локальных настроек — `Документы\MasonRecode`. Подпись вотермарка — **Admin**. В активном исходнике эта подпись была `ambient`; заменён именно этот существующий текст, без добавления нового блока.
6. Присланный `logo_transparent.png` встроен в EXE. Сохраняются форма, альфа-канал и прозрачные поля. При загрузке RGB становится белой маской, к которой применяется исходный градиент белый → Accent color. Поэтому новый логотип меняется вместе с темой и в меню, и в вотермарке. Исходное свечение логотипа сохранено.

Вспомогательная старая папка `product/menu` была отдельным урезанным примером, не интерфейсом собираемого исходного проекта. В этой сборке используется полная активная версия из `product/everness/src/alice`, без подмены на пример.

## Управление

- **Insert** — показать/скрыть меню. При запуске меню уже открыто.
- **End** — полностью закрыть оверлей.
- Скрытое меню не перехватывает мышь; включённые виджеты могут оставаться видимыми.
- При открытом меню можно перемещать меню и виджеты. Существующие всплывающие настройки открываются так же, как в оригинале.
- Настройки UI (тема, свечение, видимость виджетов) и локальные конфиги работают намеренно: это функции самого интерфейса, не чит-функции.
- Бинды переключают только локальные состояния/индикацию. Они не отправляют нажатия в другие приложения.

## Сборка на GitHub — рекомендуемый способ

1. Распакуйте `MasonOverlay-source.zip`.
2. Поместите **содержимое** папки `MasonOverlay` в корень репозитория. Не загружайте только ZIP и не оставляйте дополнительный уровень папок.
3. В корне репозитория должны быть `CMakeLists.txt`, `product`, `assets`, `tests` и `.github`.
4. Workflow уже находится в **`.github/workflows/build.yml`**. Если создаёте его через сайт GitHub, откройте Add file → Create new file, введите именно этот путь и вставьте содержимое приложенного `build.yml`.
5. После коммита откройте **Actions → Build Mason Overlay**. Он запускается при push, pull request или вручную через Run workflow.
6. После успешной сборки откройте запуск и скачайте артефакт **MasonOverlay-Windows-x64**. Внутри будет **MasonOverlay.exe**.

Внешние C++-зависимости через vcpkg не скачиваются: исходные ImGui, FreeType, JSON и изображения уже включены. Компилятор, Windows SDK и CMake предоставляет runner `windows-2022`. Используется Visual Studio 2022, x64, Release и статическая CRT. Старый toolset из присланного проекта не нужен.

Проверка `--smoke-test` запускает тот же EXE с программным Direct3D (WARP), рисует 30 кадров и завершает его. В workflow есть ограничение времени и проверка кода выхода. Это не игровой тест, не инжектор и не загрузчик.

## Локальная сборка (необязательно)

Нужны Visual Studio 2022 с компонентом «Разработка классических приложений на C++», Windows SDK и CMake 3.20+.

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release --parallel 2
.\build\Release\MasonOverlay.exe
```

Готовый файл — `build\Release\MasonOverlay.exe`. Рядом не нужно держать PNG, папку ресурсов или DLL из исходного проекта.

## Конфиги и виджеты

- Менеджер работает только с локальными файлами `Документы\MasonRecode\*.cfg`.
- Подпапка для отображения списка звуков: `Документы\MasonRecode\killsound`. Выбор файла не воспроизводит звук.
- Старые конфиги автоматически не импортируются и не изменяются.
- Hit logs использует исходные демонстрационные строки при открытом меню — это не события какой-либо игры.
- Положение виджетов и отсутствие сохранения ImGui INI оставлены как в исходном интерфейсе; их можно расположить мышью.

## Требования и границы

Windows 10/11 x64, обычный рабочий стол с Direct3D 11. Оверлей создаёт собственное прозрачное окно поверх основного монитора. В эксклюзивном полноэкранном режиме стороннее окно может не отображаться; используйте оконный/безрамочный режим. Никаких обходов захвата, античитов или внедрения в полноэкранное приложение нет.

## Проверки

```powershell
python tests/verify_source.py
python tests/verify_source.py --exe build/Release/MasonOverlay.exe
.\build\Release\MasonOverlay.exe --smoke-test
```

`verify_source.py` проверяет сохранённые исходные файлы интерфейса, наличие всех вкладок, встроенный PNG и отсутствие прежних игровых модулей/вызовов. При передаче EXE также проверяются формат x64 GUI EXE (не DLL) и таблица импортов. Это технические проверки, а не обещание совместимости со всеми компьютерами или результат антивирусной сертификации.

Проект подготовлен в Linux-среде. Финальная Windows-сборка и Direct3D-тест выполняются workflow на GitHub; успешная сборка на GitHub не утверждается до запуска этого workflow.

Исходные лицензии и авторские уведомления сторонних библиотек сохранены. Права на исходный интерфейс, шрифты и предоставленный логотип остаются у их правообладателей.
